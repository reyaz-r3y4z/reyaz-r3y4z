Module 01
Resampling & Cross-Validation
How to evaluate models honestly — protecting against overfitting and data leakage.
🔀
Standard K-Fold Cross-Validation
▾
Analogy

Like grading an exam by testing students on 5 different question sets in rotation — each time one set is the exam, the others are study material. The final grade is the average across all 5 rotations.

The full dataset $\mathcal{D}$ is split into $K$ equal non-overlapping folds. Each iteration holds out one fold as validation and trains on the remaining $K-1$. The final score is the mean across all $K$ iterations:

Mean CV Score
$\mathbb{E}[\mathcal{M}] = \frac{1}{K} \sum_{i=1}^{K} \mathcal{M}_i$
Fold 1 is the validation set
Validation fold
Training folds
When to use

Default baseline for i.i.d. tabular data where observations are independent. Use $K=5$ or $K=10$. Not appropriate for time-series or heavily imbalanced data.

⚡

Interview answer: K-Fold gives a lower-variance estimate of generalisation error than a single train/test split. The trade-off is $K$× the compute cost.

⚖️
Stratified K-Fold
▾

The problem: With a 99%/1% class imbalance, a random fold could contain zero minority-class examples — making precision and recall undefined and the fold useless.

Stratified K-Fold mathematically forces every fold to mirror the exact class distribution of the parent dataset. If the dataset is 10% positive, every fold is exactly 10% positive.

Fraud detectionMedical diagnosisImbalanced datasets
⚡

Interview trigger: Any time you see class imbalance, immediately mention Stratified K-Fold before anything else.

📈
Time-Series Split (Forward Chaining)
▾
Analogy

A financial analyst forecasting next month's revenue using only historical data up to that point — never peeking at future months to calibrate the model.

Standard K-Fold would cause data leakage — training on future data to predict the past. Time-series split uses a chronological expanding window: the validation set is always strictly ahead of the training set in time.

Multicollinearity & VIF
▾

When two or more independent features are highly correlated, the OLS engine cannot isolate their individual contributions. The matrix inversion $(\mathbf{X}^T\mathbf{X})^{-1}$ approaches near-singularity, inflating coefficient standard errors.

Predictive paradox: Multicollinearity does NOT degrade the model's overall $R^2$ or predictive power. It only destroys parameter interpretation and model stability.

Variance Inflation Factor
VIF Formula
$\text{VIF}(X_i) = \frac{1}{1 - R_i^2}$

$R_i^2$ = the $R^2$ from regressing feature $X_i$ against all other features. High $R_i^2$ means other features explain $X_i$ well — severe multicollinearity.

VIF = 1 (orthogonal)VIF = 5VIF ≥ 10 (severe)
VIF = 1
No Collinearity
Feature is completely independent of all others.
VIF 1–5
Moderate
Some correlation. Monitor but often acceptable.
VIF ≥ 10
Severe
Drop one feature, apply PCA, or switch to Ridge.
Module 02
Parametric Models
Linear and logistic regression — assumptions, diagnostics, and failure modes.
📐
Linear Regression — Gauss-Markov Assumptions
▾
Analogy

A tailor fitting a rigid wooden ramp over stepping stones — they can only tilt it (slope) and shift it up/down (intercept) to minimise the vertical gap to each stone. The ramp cannot bend.

The 4 Gauss-Markov Assumptions (B.L.U.E.)
Assumption 1
Linearity
Relationship between $X$ and $\mathbb{E}[Y]$ must be linear. Check: Residuals vs Fitted plot — look for curved patterns.
Assumption 2
Independence of Errors
No autocorrelation. Check: Durbin-Watson test. Value ≈ 2 = no autocorrelation. Values near 0 = positive autocorrelation.
Assumption 3
Homoscedasticity
Constant error variance. Check: Residuals vs Fitted — funnel shape = heteroscedasticity. Fix: log or Box-Cox transform on Y.
Assumption 4
Normality of Residuals
Errors must be normally distributed for valid hypothesis tests. Check: Q-Q plot — points should lie on the 45° diagonal line.
Evaluation Metrics
MAE — Robust to outliers
$\text{MAE} = \frac{1}{n}\sum_{i=1}^{n}|y_i - \hat{y}_i|$
RMSE — Penalises large errors heavily
$\text{RMSE} = \sqrt{\frac{1}{n}\sum_{i=1}^{n}(y_i - \hat{y}_i)^2}$
Adjusted R² — Penalises for adding useless features
$R^2_{\text{adj}} = 1 - \left[\frac{(1-R^2)(n-1)}{n-p-1}\right]$
⚡

Key point: Standard $R^2$ always increases when you add features. Adjusted $R^2$ penalises for feature count — use it to compare models of different complexity.

📊
Logistic Regression — Core Mechanics
▾
Analogy

A credit card fraud system with a dimmer switch — instead of abruptly blocking or allowing a transaction, it smoothly scales a fraud probability from 0 to 1 based on incoming signals.

Logistic regression models probability $P$ that an observation belongs to a class. It maps a linear combination of features to the non-linear [0,1] range using the Logit Link Function:

Logit (Log-Odds)
$\text{logit}(P) = \ln\left(\frac{P}{1-P}\right) = \beta_0 + \beta_1 X_1 + \dots + \beta_p X_p$
Sigmoid — inverse of logit, solving for P
$P = \frac{1}{1 + e^{-(\beta_0 + \beta_1 X_1 + \dots + \beta_p X_p)}}$
Critical Assumption — Linearity of the Logit

Logistic regression does NOT need a linear relationship between $X$ and $P$. It needs linearity between $X$ and the log-odds. Check: Box-Tidwell test — adds $X \cdot \ln(X)$ interaction terms.

Complete Separation — Classic Interview Trap
🔥

The problem: If a feature perfectly separates classes (e.g. every patient with BP > 180 is sick), MLE drives the coefficient toward infinity. The algorithm fails to converge.

Fix: Apply L2 (Ridge) regularisation to constrain coefficient magnitudes.

🎯
Partial Correlation — Isolating Variables
▾

In multiple regression, $\beta_1$ is a partial coefficient — the expected change in $Y$ per 1-unit increase in $X_1$ after removing the linear influence of all other features from both $X_1$ and $Y$.

3-Step Partial Correlation Routine
1
Regress Y on X₂
Collect residuals $e_{Y \cdot X_2}$ — the variance in Y that X₂ cannot explain.
↓
2
Regress X₁ on X₂
Collect residuals $e_{X_1 \cdot X_2}$ — the variance in X₁ that X₂ cannot explain.
↓
3
Correlate the two residuals
$r_{YX_1 \cdot X_2} = \text{corr}(e_{Y \cdot X_2},\; e_{X_1 \cdot X_2})$ — the pure X₁↔Y relationship with X₂ held constant.
Module 03
Distance & Probabilistic Classifiers
SVM, Naive Bayes, KNN — and mastering the confusion matrix.
🗺️
SVM, Naive Bayes, KNN — Mental Models
▾
SVM
The Surveyor
Draws the widest possible margin border between two classes. Only the support vectors (boundary points) matter. Kernel trick maps to higher dimensions for non-linear separation.
Naive Bayes
The Quick Clerk
Calculates a running probability tally based on feature frequencies assuming all features are independent given the class. "Naive" because this independence assumption is almost always false.
KNN
The Local Vote
Assigns a label by majority vote among the K nearest neighbours in feature space. No training phase — all computation happens at prediction time (lazy learner).
Feature Scaling — Critical for SVM and KNN

Distance-based algorithms (SVM, KNN) are dominated by features with large ranges. Income ($500K) will completely overwhelm Age (100) in Euclidean distance.

Always apply: Z-score standardisation (mean=0, std=1) or Min-Max scaling [0,1] before using distance-based models.

⚡

Naive Bayes paradox: Despite its unrealistic independence assumption, it performs remarkably well for text classification — it ranks class probabilities correctly even if the exact probabilities are wrong.

XGBoost · LightGBM · CatBoost — Key Differences
▾
XGBoost
Regularised GB
L1+L2 regularisation in objective. Uses second-order derivatives (Hessians) for faster convergence. Pre-sorted block system for split-finding. Gold standard for tabular data.
LightGBM
Leaf-Wise Growth
Grows the single leaf that reduces loss the most regardless of depth. GOSS samples high-gradient instances. EFB bundles sparse features. Fastest and most memory-efficient on large datasets.
CatBoost
Ordered Boosting
Handles raw categoricals natively — no encoding needed. Ordered boosting uses dataset permutations to evaluate splits, completely preventing target leakage on categoricals.
SHAP Values — Beyond Feature Importance

Traditional feature importance is unstable — if two features are correlated, a tree may assign all importance to one and ignore the other.

SHAP (Shapley Additive Explanations) — based on cooperative game theory — computes each feature's unique marginal contribution across all possible feature combinations. Provides both global and local (per-prediction) explanations.

Hyperparameter Optimisation
▾
Grid Search
Exhaustive
Tests every combination in a predefined grid. Guaranteed to find the best within grid bounds. Computationally expensive — scales exponentially with dimensionality.
Random Search
Probabilistic
Randomly samples combinations from distributions. Mathematically proven to find near-optimal results much faster by skipping irrelevant parameter regions.
Bayesian Opt.
Surrogate Model
Builds a Gaussian Process to predict performance from past runs. Uses an acquisition function to balance exploration vs exploitation. Most sample-efficient method.
Module 05
Unsupervised Learning
Clustering and dimensionality reduction — finding structure without labels.
🔵
K-Means vs DBSCAN
▾
K-Means
Centroid-Based

Iteratively assigns points to nearest centroid, then recomputes centroids as cluster means. Repeats until convergence.

Limitations:

• Requires pre-specifying K

• Only works on spherical clusters

• Sensitive to outliers (pulls centroids)

DBSCAN
Density-Based

Groups points by density — uses a search radius ε and minimum sample threshold. Classifies each point as Core, Border, or Noise.

Advantages:

• No need to specify K upfront

• Handles non-spherical geometries

• Automatically identifies outliers as Noise

Evaluation Methods
Elbow Method
Plot Within-Cluster Sum of Squares (WCSS) against K. Look for the "elbow" — the inflection point where adding more clusters gives diminishing returns.
Silhouette Score
Measures how similar each point is to its own cluster vs neighbouring clusters. Range: −1 (wrong cluster) to +1 (well-matched). Target > 0.5.
📉
PCA vs t-SNE
▾
PCA
Linear · Transformative
Finds orthogonal axes (principal components) that maximise variance. Plot Cumulative Explained Variance Ratio — use enough components to capture ≥85–90% of total variance. Can transform new unseen data.
t-SNE
Non-linear · Visualisation Only
Probabilistically maps high-dimensional data to 2D/3D while preserving local neighbourhoods. Does NOT preserve global distances. Cannot transform new data points. Strictly a visualisation tool.
⚡

Interview trap: "Can you use t-SNE in a production pipeline?" — No. t-SNE cannot transform unseen data and distorts global distances. Use PCA or UMAP for production dimensionality reduction.

Module 06
Reinforcement Learning
Agents, environments, rewards, and the exploration-exploitation dilemma.
🐕
RL Framework — Agent, Environment, Reward
▾
Analogy

A puppy learning an obstacle course through treats and whistles — it observes its position (State), chooses to jump or run (Action), and receives a treat (Reward+) or whistle (Reward−). Over time it learns which sequence of actions maximises treats.

[ ENVIRONMENT ]
   State($S_t$) ↙         ↘ Reward($R_t$)
[ AGENT ] ──────────────────→ [ ACTION ($A_t$) ]
Cumulative Discounted Reward (Goal)
$G_t = \sum_{k=0}^{\infty} \gamma^k R_{t+k+1}$

$\gamma \in [0,1]$ is the discount factor. $\gamma = 0$ means the agent is myopic (only cares about immediate reward). $\gamma \approx 1$ means it values all future rewards equally.

The 3 Major Bottlenecks
Sample Inefficiency
Requires millions of simulated interactions to learn basic policies. Expensive and impractical for real-world deployment without simulation.
Credit Assignment
When a reward comes at the end of a long action sequence, it's hard to identify which specific past action caused the success or failure.
Explore vs Exploit
Balance testing unknown actions (explore for potentially better long-term rewards) vs repeating known good actions (exploit for reliable payouts).

Multi-Modal Models & Multi-Agent Systems
CLIP architecture, contrastive loss, and collaborative AI pipelines.
🖼️
CLIP — Multi-Modal Alignment
▾

CLIP connects images and text in a single shared embedding space using dual encoders and contrastive learning — enabling zero-shot image classification.

Image Input → [ Vision Transformer Encoder ] ──→
                                           [ Shared Embedding Space ]
Text Input  → [ Text Transformer Encoder ]  ──→
Training Objective
Contrastive Loss
Maximise cosine similarity between matching image-text pairs (diagonal of batch matrix). Minimise similarity for all mismatched pairs in the same batch.
Superpower
Zero-Shot Transfer
At inference, compute similarity between an image embedding and all candidate text class embeddings. No fine-tuning needed on target task.
🤝
Multi-Agent Systems
▾

Instead of one large model handling a complex task end-to-end, a multi-agent system distributes work across specialised autonomous agents collaborating via structured message passing.

1
Architect Agent
Receives goal. Writes technical specification with system prompt + tools (e.g. web search).
↓ passes spec
2
Developer Agent
Receives spec. Generates code with dedicated terminal/execution tools.
↓ passes code
3
Reviewer Agent
Tests code. If bugs found, sends structured feedback back to Developer Agent. Loop until passing.
⚡

Each agent has a distinct persona, custom system prompt, and tailored tool access. They communicate via structured messages — not raw text.

Module 08
LLMs & Retrieval-Augmented Generation
How large language models work — and how RAG fixes hallucination at its root.
🧠
LLMs — Architecture & Root Cause of Hallucination
▾

Modern LLMs are Transformer Decoder architectures. They process tokens in parallel using self-attention and are pre-trained via autoregressive next-token prediction on massive datasets.

🔥

Root cause of hallucination: LLMs are probabilistic text-generation engines, not factual databases. They optimise for linguistic plausibility — the most statistically likely next token given context — not for factual correctness. They have no internal truth-verification mechanism.

Key Terminology
Context Window
Maximum number of tokens an LLM can process in a single forward pass. Everything outside this window is invisible to the model.
Temperature
Controls sampling randomness. Low (~0.1) = deterministic/factual. High (~1.0) = creative/variable. Temperature=0 = always pick the highest probability token.
Fine-Tuning
Updating model weights on domain-specific data. Expensive. Teaches style/format well but doesn't reliably inject current facts.
RAG
Retrieval-Augmented Generation — inject external verified facts at inference time. Cheaper and more updatable than fine-tuning for factual grounding.
🔍
RAG Pipeline — End-to-End
▾
Phase 1 — Ingestion Pipeline
1
Chunking
Raw documents split into small coherent segments using fixed-size or semantic boundaries to preserve local context.
↓
2
Dense Embedding
Each chunk passed through an embedding model → high-dimensional vector capturing semantic meaning.
↓
3
Vector Database Storage
Vectors indexed in Pinecone / Milvus / FAISS with original text metadata attached.
Phase 2 — Inference Loop
4
Query Embedding
User query converted to vector using the same embedding model. Cosine similarity search retrieves Top-K most relevant chunks.
↓
5
Prompt Augmentation
Retrieved chunks injected directly into the system prompt as reference context alongside the user's query.
↓
6
Grounded Generation
LLM generates an answer using only the provided context — preventing hallucination from internal weights.
RAG Triad Evaluation
Context Relevance
Are the retrieved chunks focused and relevant to the query? Measures retrieval quality — is the vector DB returning signal or noise?
Groundedness
Is the LLM's response derived strictly from retrieved context? Detects when the model hallucinates from its training weights instead of the provided source.
Answer Relevance
Does the final output actually answer the user's question? The retrieved context can be perfect but the response can still miss the point.
